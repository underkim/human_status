## 2. 로컬 저장 원칙

Human Status의 스텟, 퀘스트, 목표, 거래, 자산, 재무 계획 및 설정은 계정이나
서버 동기화 없이 사용자의 기기에 저장됩니다.

Claude API 키는 지원되는 플랫폼(Android/iOS/macOS/Windows/Linux)에서는 보안
저장소(Android Keystore, iOS/macOS Keychain, Windows DPAPI, Linux
libsecret)에 저장되고, 백업 파일에서는 제외됩니다. 웹에서는 브라우저에
저장되는 값의 보호 수준이 상대적으로 낮습니다.

## 3. 선택적 크래시 리포팅

익명 크래시 리포팅의 기본값은 꺼짐입니다. 사용자가 설정 화면에서 명시적으로
켠 경우에만 Sentry SDK를 초기화하고, 그 이후 발생하는 오류 정보를 Sentry로
전송합니다. 설정에서 끄면 이후 신규 오류 전송을 즉시 중단합니다.

동의하기 전에는 어떤 형태의 진단 이벤트도 외부로 전송되지 않으며, SDK 자체가
초기화되지도 않습니다.

## 4. 전송될 수 있는 정보

크래시 리포팅을 켠 뒤 오류가 발생하면 다음과 같은 정보가 Sentry로 전송될 수
있습니다.

- 예외 종류와 메시지, Dart/Flutter stack trace(함수·파일명·줄 번호, 경우에
  따라 파일 경로 일부)
- 오류 발생 시각
- 앱 이름·버전·빌드 번호, release/environment 식별자, Sentry SDK 버전
- 실행 플랫폼, 기기 제조사·모델·아키텍처, OS 이름·버전·빌드
- locale/timezone
- 메모리·디스크 여유 공간, 앱이 foreground/background 상태였는지 같은
  런타임/기기 상태
- 무작위로 생성되는 이벤트 ID

브라우저(웹)에서는 위 항목에 더해 SDK/브라우저 통합이 브라우저 이름·버전,
user agent, 현재 페이지 URL/referrer를 함께 포함시킬 수 있습니다. 이 앱은
전송 직전 필터(`beforeSend`)로 URL의 query string과 fragment를 제거합니다.

이벤트를 Sentry로 전송하는 네트워크 요청 과정에서 발신 IP 주소가 Sentry
서비스에 의해 처리될 수 있습니다. 이 앱은 `sendDefaultPii`를 꺼서 사용자
식별자나 IP를 이벤트에 직접 채워 넣지 않지만, 전송 자체가 발생하는 이상
네트워크 계층의 IP 처리 가능성까지 없앨 수는 없습니다. 실제 Sentry 프로젝트의
IP 저장/삭제(스크러빙) 설정은 아래 7절에서 확정합니다.

## 5. 수집하지 않도록 설계한 정보

다음 정보는 크래시 리포팅 이벤트에 의도적으로 포함하지 않습니다.

- 이름, 이메일, 계정 ID, 광고 ID 등 사용자를 직접 식별하는 정보
- 퀘스트·목표·거래 등 앱에 기록한 원문 데이터, 백업 파일 내용
- Claude API 키
- 스크린샷, 세션 리플레이(Session Replay), 성능 추적(trace) 데이터

단, 예외 메시지나 stack trace의 파일 경로에 위 정보의 일부가 우발적으로
포함될 가능성은 완전히 배제할 수 없습니다. 이 앱은 전송 전 필터로 Claude API
키 형태(`sk-ant-...`)의 문자열과 로컬 절대 경로를 최대한 걸러내지만, 100%
제거를 보장하지는 않습니다.

## 9. 동의 철회

설정 화면의 "익명 크래시 리포팅" 스위치를 끄면 다음이 즉시 적용됩니다.

- 이 앱이 관리하는 수동 오류 전송 경로(예외/크래시 캡처)가 즉시 막혀, 이후
  발생하는 오류에 대한 신규 이벤트 전송이 중단됩니다.
- 사용 중인 Sentry SDK 종료 API가 호출되어 현재 세션의 SDK 연결이 정리됩니다.

다만 이 종료 API는 "이미 기기에 캐시된 미전송 이벤트를 강제로 폐기"하는
기능이 아니라 SDK/연동을 정리하는 기능입니다. 특히 Android/iOS의 네이티브
크래시 핸들러가 별도로 캐시해 둔 이벤트는 이 종료 호출 이후에도 계속
처리·전송될 수 있습니다(사용하는 네이티브 백엔드에 따라 다름). 즉, 스위치를
끄는 순간 기기에 남아 있던 모든 미전송 이벤트가 100% 즉시 삭제된다고
보장하지 않으며, 이 앱은 그 가능성을 낮추기 위해 신규 전송 경로만큼은
지체 없이 차단합니다.

이미 Sentry로 전송이 완료된 과거 이벤트는 로컬에서 스위치를 끄는 것만으로
즉시 삭제되지 않으며, 8절의 보관 기간 경과 또는 1절의 문의 채널을 통한 별도
삭제 요청에 따라 처리됩니다.

## 10. 오프라인과 재전송

전송에 실패한 이벤트를 SDK가 기기에 잠시 보관했다가 재시도할 수 있습니다.

- Dart/Flutter 계층의 전송(sentry 8.14.2 기준 `HttpTransport`)은 디스크에
  영구 캐시를 두지 않고, 동시에 진행 중인 전송 작업 수만 메모리상 최대
  30개로 제한합니다 — 그 이상은 재시도 없이 버려집니다.
- Android/iOS의 네이티브 통합은 이와 별개로 자체적인 크래시 캐시를 가질 수
  있습니다. 이 캐시의 정확한 최대 보관량/기간은 각 플랫폼 네이티브 SDK
  구현에 달려 있어 이 문서가 숫자로 보장하지 않습니다.
- 이 앱의 "익명 크래시 리포팅" 동의는 앱 레벨의 신규 전송 게이트입니다.
  동의가 켜져 있는 동안에는 재연결 시 이 게이트를 통해 재전송이 시도될 수
  있고, 동의를 끄면 이 게이트가 즉시 닫혀 이 앱이 새로 트리거하는 신규
  전송·재연결 재시도는 더 이상 발생하지 않습니다.
- 다만 9절에서 설명하듯, 이 게이트를 닫는 것과 "기기에 남아 있던 모든
  이벤트의 처리를 그 순간 완전히 중단시키는 것"은 같지 않습니다. 게이트가
  닫히기 직전까지 이미 전송이 시작된 요청이나, Android/iOS 네이티브 크래시
  핸들러가 별도로 캐시해 둔 이벤트는 이 앱의 신규 전송 게이트와 무관하게
  백그라운드에서 계속 처리·전송될 수 있습니다. 즉, 동의를 끈 뒤에도 이런
  경로로는 이벤트가 나갈 가능성이 남아 있으며, 이 앱은 그 가능성을 낮추기
  위해 자신이 통제할 수 있는 신규 전송 경로만큼은 지체 없이 차단합니다.
- 웹 브라우저에서는 네이티브 플랫폼과 동일한 영속적 오프라인 큐가 보장되지
  않으며, 이 경우 이벤트 유실을 정상적인 동작으로 간주합니다.
